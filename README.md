# 市場溫度計 — Market Thermometer

VIX · VVIX · 台指選擇權 Put/Call 未平倉量比 · ADL 騰落指標 四項加權成一個 0–100 的
綜合分數，對應到 0050 定期定額的扣款倍率；另外附一塊「融資警戒」看散戶槓桿水位與
三層斷頭風險。全部資料每天由 GitHub 自動抓取、自動重算、自動更新網頁。

- **不用開電腦**：抓資料跑在 GitHub 的機器上。
- **不用付錢**：資料源都是公開端點；AI 評論用 Gemini 的免費額度。
- **手機也能看**：部署完會有一個公開網址，可以加到主畫面當 App 用。

## 一、完成後你會有什麼

一個像這樣的網址：`https://你的帳號.github.io/market-thermometer/`

頁面上會有：

| 區塊 | 內容 |
|---|---|
| 溫度計 + 綜合分數 | 0–100 分、市場狀態、與昨日的變化 |
| 今日建議 | 對應的 0050 定期定額扣款倍率（80% / 100% / 120% / 150~200%） |
| 市場狀態判定 | 四段區間的完整說明，當前所在的那一段會亮起來 |
| 四張指標卡 | VIX、VVIX、P/C Ratio、ADL 的數值、子分數、門檻說明，各附一句白話解讀 |
| 融資警戒 | 融資餘額、位階（30/60/90/180 日可切）、三層斷頭風險、槓桿動能、每日文字評論 |
| TAIEX 條 | 昨收／今開／收盤、開盤跳空與追繳門檻、盤中累積、台指期夜盤隔夜跳空 |
| 總經事件 | 即將發生的 FOMC、CPI、非農就業、台指期結算，並在走勢圖上標記過去事件 |
| 走勢圖 | 綜合分數與 0050 收盤價兩張連動圖，可切 30 / 90 / 180 日 / 全部 |
| 頁首狀態 | 美股／台股各自的資料日期、下次更新倒數、抓取成功與否 |

畫面上幾乎每個數字都可以把滑鼠移上去看它的**完整推導**——三層風險的統計依據與維持率
數學、P25/P75 各是多少天、追繳門檻怎麼來的，都寫在 tooltip 裡。

## 二、部署步驟（照著做就好）

整個流程大約 15 分鐘。你不需要看懂任何一行程式碼。

### 步驟 1：申請 Gemini 免費 API key

Google 的 Gemini 是三家裡面唯一有**免費額度**的（Flash 系列模型的免費層不收費，
不需要綁信用卡就能開始用）。Anthropic 與 OpenAI 都是預付／後付制，新帳號雖然可能
有少量試用額度，但不是長期免費，所以這裡選 Gemini。

1. 打開 **https://aistudio.google.com/apikey**
2. 用你的 Google 帳號登入
3. 同意服務條款 → 系統會自動幫你建一個 API key
4. 按複製，先貼到記事本，等一下要用
   （這串等同密碼，不要貼到任何公開的地方、也不要貼進程式碼裡）

> 想省事的話這一步可以先跳過。沒有 key 的時候網頁上的每日評論會改用內建的
> 規則式文字，其他功能完全不受影響，之後想加再加。

### 步驟 2：建立 GitHub 帳號與 repo

1. 沒有帳號的話先去 **https://github.com/signup** 註冊（免費）
2. 登入後點右上角 **+** → **New repository**
3. Repository name 填 `market-thermometer`
4. 選 **Public**
   - ⚠️ 這一點很重要：GitHub Pages 在**免費方案下只支援 public repo**。
     選 Private 的話網頁不會生成。
   - Public 不會洩漏你的 API key——key 是存在 GitHub 的加密 Secrets 裡，
     不在程式碼裡，別人看不到。
5. 其他不用改，點 **Create repository**

### 步驟 3：上傳專案檔案

1. 在剛建好的 repo 頁面點 **uploading an existing file**
   （或 **Add file** → **Upload files**）
2. 把我給你的壓縮檔**解開**，然後把裡面的**所有東西**（包含 `.github` 這個資料夾）
   一起拖進上傳區
   - 如果瀏覽器不讓你拖 `.github` 資料夾，改用「Add file → Create new file」，
     檔名直接打 `.github/workflows/update.yml`，再把該檔內容貼進去。
3. 下方 **Commit changes** 按下去

### 步驟 4：把 API key 存成 Secret

1. repo 頁面上方 **Settings**
2. 左邊選單 **Secrets and variables** → **Actions**
3. 點 **New repository secret**
4. Name 填 `GEMINI_API_KEY`（大小寫要一模一樣）
5. Secret 貼上步驟 1 複製的那串
6. **Add secret**

### 步驟 5：跑第一次歷史回補

第一次要把過去的資料補起來，走勢圖才會有東西看。

1. repo 上方 **Actions**
2. 如果出現「Workflows aren't being run on this forked repository」或要你確認的
   畫面，點綠色按鈕同意啟用
3. 左邊點 **更新市場溫度計資料**
4. 右邊 **Run workflow** → 在 `backfill` 欄位填 **240** → 點綠色 **Run workflow**
5. 等 5～15 分鐘（證交所有流量限制，程式會自己放慢速度慢慢抓，這是正常的）
6. 跑完後看到綠色勾勾就成功了

> 之後**不用**再填 backfill，每天的排程會自動接著往下累積。

### 步驟 6：打開 GitHub Pages

1. **Settings** → 左邊 **Pages**
2. Source 選 **Deploy from a branch**
3. Branch 選 **main**，資料夾選 **/docs**，按 **Save**
4. 等 1～3 分鐘，同一頁上方會出現你的網址

### 步驟 7：驗證

打開網址，檢查這幾件事：

- [ ] 溫度計有數字，不是「載入資料中」
- [ ] 右上角「美股資料 / 台股資料」有日期
- [ ] 右上角有寫「評論來源 AI」→ 表示 Gemini key 有生效
      （寫「規則式」就是 key 沒設或呼叫失敗，其他功能仍正常）
- [ ] 下方走勢圖有一長段線，不是只有幾個點
- [ ] 手機打開也正常（可以「加入主畫面」當 App）

## 三、每天會自動發生什麼

| 台北時間 | 做什麼 |
|---|---|
| 22:00（週一～週五） | 抓台股：漲跌證券數（ADL 原料）、融資餘額、加權指數、0050 |
| 隔日 06:00（週一～週五） | 抓美股：VIX、VVIX（此時美股日 K 已定案，夏令冬令都覆蓋） |

每次跑完會把 `docs/data/` 底下的 JSON 更新並自動 commit，網頁隨之更新。

兩件關於 GitHub 排程要知道的事：

- 免費方案的 cron 可能會**延遲幾分鐘到一小時**才觸發，這是 GitHub 的常態，不是壞了。
- 如果一個 repo **連續 60 天沒有任何活動**，GitHub 會自動停用排程。本專案每天都會
  commit 資料，所以只要它在跑就不會被停；真的被停了，去 Actions 頁面按一下
  「Enable workflow」即可。

## 四、想調整權重或門檻

打開 `config.yaml`，在 GitHub 網頁上直接點鉛筆圖示就能改，**不用碰程式碼**。

```yaml
weights:
  vix:  0.45   # 想更看重台股廣度就把 adl 調高、vix 調低
  adl:  0.30
  vvix: 0.15
  pcr:  0.10   # 四個加起來必須是 1.0

thresholds:
  vix:
    best: 13     # ≤13 → 100 分
    worst: 30    # ≥30 → 0 分
```

改完 commit，下一次排程就會用新參數把**整段歷史重算一次**（走勢圖也會跟著變），
不用等新資料進來。想立刻看到結果就去 Actions 手動 Run workflow 一次（backfill 留空）。

其他常見調整：

- `regimes` 裡的 `min` 與 `dca_label`：改變四段狀態的分界與扣款倍率。
- `margin.triggers`：改三層斷頭風險的門檻。
- `commentary.provider`：改成 `anthropic` / `openai` / `none`。
  換家的話記得同時去 Secrets 加對應的 `ANTHROPIC_API_KEY` 或 `OPENAI_API_KEY`。

## 五、分數怎麼算出來的

### 四個子分數

| 指標 | 權重 | 滿分 | 零分 | 資料源 |
|---|---|---|---|---|
| VIX 美股恐慌指數 | 45% | ≤13 | ≥30 | Yahoo Finance `^VIX` |
| ADL 騰落指標 10MA 斜率 | 30% | 多頭擴散 | 空頭破底 | 證交所漲跌證券數 |
| VVIX 波動率的波動率 | 15% | ≤85 | ≥125 | Yahoo Finance `^VVIX` |
| 台指選擇權 P/C 未平倉量比 | 10% | ≥130% | ≤80% | 期交所 Put/Call 比 |

前三項是在滿分與零分之間線性插值。P/C 是**逆向解讀**——比值高代表法人在偏多防守，
所以高分。四項加權平均就是綜合分數；某一項當天缺資料時，它的權重會按比例分給其他項，
不會讓分數整體塌掉。

### ADL 的算法

1. 淨家數 = 當日上漲家數 − 下跌家數（用整體市場，含 ETF 與權證）。
2. 騰落線 = 滾動 23 個交易日的淨家數總和。
3. 取 10 日均線，再算 5 日的每日平均斜率。
4. 斜率除以「歷史斜率的標準差」做標準化，再用 tanh 壓進 0–100，50 分代表廣度持平。

第 4 步用標準差而不是直接除以總家數，是因為淨家數本身遠小於總家數；直接除的話分數
會永遠黏在 50 附近，等於白白浪費 30% 的權重。

> 誠實說明：這一項是我依公開描述重新實作的。原始網站沒有公開它的斜率→分數映射細節，
> 所以同一天我算出來的 ADL 子分數會和原站不同（方向與級別一致，數值不同）。
> 另外三項（VIX / VVIX / P/C）以及融資餘額的所有數字，我已逐項對照過原站，**完全吻合**。

### 兩套獨立的分數命名

同一個分數會同時掛兩個標籤，這是刻意的：

| 系統 | 顯示位置 | 例（80.3 分） | 在講什麼 |
|---|---|---|---|
| `market_states` | 溫度計下方 | 強勢多頭 | 市場現在是什麼**樣子** |
| `regimes` | 今日建議、狀態判定卡 | 高檔過熱 · 扣 80% | 你今天該怎麼**做** |

分段是 ≥80 / ≥60 / ≥40 / <40，兩套都可以在 `config.yaml` 各自調。

### 三層斷頭風險

| 層 | 條件 | 強訊號 | 依據 |
|---|---|---|---|
| 1. 槓桿擁擠度 | 融資餘額位階 ≥ P80 | ≥ P90 | 歷史前 20%（強訊號前 10%）高位 |
| 2. 累積跌壓 | TAIEX 近 10 日 **peak-to-current** 跌幅 ≤ −5% | ≤ −10% | 維持率 137% 的脆弱帳戶被打到 130% 斷頭線 |
| 3. 去化加速 | 融資近 3 日淨減少 ≥ 總餘額 1% | ≥ 3% | T+2 追繳週期下約等於最脆弱 5% 帳戶的集體去化量級 |

觸發 0 層＝風險低，3 層全中＝最接近真實的斷頭潮情境（維持率 130% 強制平倉）。

> **第 2 層特別注意**：這是「近 10 個交易日**最高點**跌到現價」，不是「10 日前到今天的
> 變化」。兩者差很多——先漲 10% 再跌回原點，首尾相減是 0%，peak-to-current 是 −9.1%，
> 而真正決定帳戶會不會被追繳的是後者。`tools/test_parsers.py` 有一條測試專門守這件事。

開盤跳空另外有兩個追繳門檻（同一套維持率推導）：≤ −2% 低開預警（R=133% 最脆弱 1%
帳戶觸線）、≤ −4% 嚴重低開（R=137% 脆弱 5% 帳戶觸線）。

### 總經事件行事曆

FOMC 取自 Federal Reserve 官方會議行事曆，CPI 與非農就業取自 BLS 官方發布排程，
時間全部換算成台北時間顯示（不跟隨你所在的時區）。

**非農就業不是「每月第一個週五」**——2026/07/02 是週四、2026/02/11 是週三，用土法推導
會錯，所以 `pipeline/events.py` 一律照官方排程表。唯一用規則推導的是台指期結算日
（每月第三個週三，這是期交所契約規則，可以安全往後推）。

排程表每年更新一次；表裡沒涵蓋的月份不會憑空生成日期，只會少幾筆事件。要補的時候
照 `events.py` 開頭註解裡的三個官方網址更新即可。

### 台指期夜盤隔夜跳空

期交所的「盤後交易時段(T)」跑的是 **T−1 下午 15:00 到 T 清晨 05:00** 那一夜，也就是它
**先於**同一個交易日 T 的一般交易時段。所以隔夜跳空 = 夜盤(T) 最後成交價 − 日盤(T−1)
最後成交價。這點很容易搞反，已用兩天的實際資料交叉驗證（夜盤 T 的最後成交價幾乎等於
日盤 T 的開盤價）。

## 六、遇到問題怎麼辦

**網頁顯示「讀不到資料檔」**
Actions 還沒成功跑過，或 Pages 的資料夾設錯。回步驟 5、6 檢查一次。

**Actions 出現紅色叉叉**
點進去看 log。最常見的兩個原因：

- `git push` 被拒 → repo 的 Settings → Actions → General → Workflow permissions
  要選 **Read and write permissions**。
- 證交所回 307 → 那是流量限制。程式已經內建節流與重試；偶爾整批失敗就等下一次排程，
  或手動 Run workflow 重跑，資料會自動補上。

**走勢圖只有幾個點**
沒跑過 backfill，或 backfill 中途被證交所限流。再手動 Run workflow 一次、
backfill 填 240 即可（已經抓到的日子會自動跳過，不會重複抓）。

**右上角一直寫「⚠ 今日尚未更新」**
表示今天的排程還沒跑到，或當天休市。台股要等 22:00 之後、美股要等隔日 06:00 之後。

**評論來源一直是「規則式」**
Secret 名稱要完全等於 `GEMINI_API_KEY`；或者 key 失效了。Actions 的 log 裡會印出
失敗原因（例如額度用完、模型名稱不存在）。`config.yaml` 的 `gemini_model` 換成
AI Studio 上看得到的型號即可。

**融資位階顯示 P 值怪怪的／槓桿動能寫「需要更多資料」**
位階需要 90 個交易日、動能需要一整個視窗的資料才算得出來。剛部署完資料不夠時會這樣，
跑完 backfill 就正常。切到 30d 視窗會比 180d 早幾天能看。

**總經事件清單變少或空了**
官方排程表過期了。照 `pipeline/events.py` 開頭註解裡的三個網址把新年度的日期補進
`_FOMC` / `_CPI` / `_NFP` 三張表即可。程式不會自己編日期，所以只會少事件、不會出現假日期。

**台指期夜盤那一欄消失或標示為舊資料**
期交所該次抓取失敗時會沿用上一次的值。連續幾天都沒更新就去 Actions 看 log。

## 七、檔案結構

```
market-thermometer/
├─ config.yaml                  ← 權重與門檻，要調參數只改這個檔
├─ requirements.txt
├─ .github/workflows/update.yml ← 每日排程
├─ pipeline/
│   ├─ net.py         HTTP 共用層（節流、重試）
│   ├─ sources.py     四個資料源的抓取與解析
│   ├─ scoring.py     子分數與綜合分數
│   ├─ margin.py      融資警戒、三層風險、開盤跳空
│   ├─ events.py      總經事件行事曆（官方排程表 + 結算日推導）
│   ├─ commentary.py  每日文字評論（Gemini / Claude / OpenAI / 規則式）
│   ├─ build.py       主流程
│   └─ seed.csv       初始種子資料（真實值，2026-08-11 抓取）
├─ docs/                        ← GitHub Pages 的網站根目錄
│   ├─ index.html               單一檔案，零外部相依
│   ├─ favicon.svg
│   ├─ manifest.webmanifest
│   └─ data/                    自動產生：latest / history / status
└─ tools/
    ├─ shot.py          本機截圖
    ├─ check.py         瀏覽器自我檢查（圖表、連動、倒數、tooltip、行動版）
    ├─ test_parsers.py  離線回歸測試（解析與算式，不需網路）
    └─ make_preview.py  產生單檔預覽版
```

## 八、在自己電腦上跑（選用）

不影響 GitHub 那邊，純粹想在本機看或改東西時用。需要 Python 3.11 以上。

```bash
pip install -r requirements.txt

# 只用現有歷史重算，不連網（改完 config.yaml 想快速看結果）
python -m pipeline.build --no-fetch

# 連網抓最新資料
python -m pipeline.build

# 第一次要歷史回補
python -m pipeline.build --backfill 240

# 本機開網頁看
python -m http.server -d docs 8080     # 然後打開 http://localhost:8080

# 產生「單檔預覽版」：不用伺服器、不用網路，雙擊就能開
python tools/make_preview.py

# 離線回歸測試（不需網路，改完程式先跑這個）
python tools/test_parsers.py

# 瀏覽器自我檢查（需要 pip install playwright && playwright install chromium）
cd tools && python check.py
```

> 壓縮檔裡已經附了一份 `preview.html`，直接雙擊就能看到部署後的樣子
> （資料是打包當時的快照，不會自己更新）。

想在本機也產生 AI 評論，先設環境變數：

```bash
export GEMINI_API_KEY=你的key        # Windows PowerShell：$env:GEMINI_API_KEY="你的key"
```
